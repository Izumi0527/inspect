# 后端启动脚本数据库迁移增强功能

## 概述

`scripts/start-backend.ps1` 脚本已增强,现在支持智能的数据库迁移检测和交互式选择功能。

## 新增功能

### 1. 自动迁移状态检测

脚本启动时会自动检查数据库迁移状态,包括:
- 当前数据库版本
- 最新可用迁移版本
- 是否需要迁移

### 3. 多种运行模式

#### 模式1: 自动化模式(使用 -Migrate 参数)

```powershell
# 自动执行迁移,无需用户交互
powershell.exe -File scripts/start-backend.ps1 -Dev -Migrate
```

**特点:**
- 保持向后兼容性
- 适用于 CI/CD 流水线
- 自动执行迁移,无需确认

#### 模式2: 交互模式(默认)

```powershell
# 显示交互式提示,让用户选择
powershell.exe -File scripts/start-backend.ps1 -Dev
```

**特点:**
- 显示详细的迁移状态
- 提供用户选项:执行迁移、跳过、查看历史
- 即使数据库已是最新版本,也允许手动选择

#### 模式3: 非交互环境(自动检测)

```powershell
# 在 CI/CD 或非交互环境中自动跳过提示
# 如果需要迁移,会显示警告信息
```

**特点:**
- 自动检测是否为交互式终端
- 非交互环境自动跳过提示
- 显示警告信息提醒用户使用 -Migrate 参数

## 迁移状态说明

### 状态类型

| 状态 | 图标 | 说明 |
|------|------|------|
| up-to-date | ✓ 已是最新 | 数据库已是最新版本 |
| behind | ⚠ 需要迁移 | 数据库需要更新到最新版本 |
| no-database | ⚠ 需要初始化 | 数据库未初始化或无迁移记录 |
| no-config | ✗ 配置缺失 | 未找到 alembic.ini 配置文件 |
| error | ✗ 检查失败 | 检查迁移状态时发生错误 |

## 技术实现

### 核心函数

#### Get-MigrationStatus

获取数据库迁移状态,返回包含以下信息的对象:

```powershell
@{
    Current = "当前版本号"
    Target = "目标版本号"
    NeedsMigration = $true/$false
    Status = "up-to-date" / "behind" / "ahead" / "no-database" / "error"
    Message = "状态描述信息"
}
```

**实现原理:**
1. 执行 `uv run alembic current` 获取当前版本
2. 执行 `uv run alembic heads` 获取目标版本
3. 逐行解析输出,提取版本号
4. 比较版本,判断迁移状态

#### Show-MigrationPrompt

显示迁移状态并获取用户选择。

**支持选项:**
- `[Y]` - 执行迁移
- `[N]` - 跳过迁移
- `[V]` - 查看历史(显示后重新提示)
- `[S]` - 跳过迁移(同N)

**返回值:**
- `"migrate"` - 用户选择执行迁移
- `"skip"` - 用户选择跳过迁移

#### Invoke-DatabaseMigration

增强的数据库迁移函数。

**工作流程:**
1. 调用 Get-MigrationStatus 检查状态
2. 判断运行模式:
   - 指定 `-Migrate` → 自动执行
   - 交互环境 → 显示提示
   - 非交互环境 → 跳过并警告
3. 根据选择执行迁移
4. 显示迁移结果

## 常见问题

### Q: 如何在不交互的情况下自动迁移?

A: 使用 `-Migrate` 参数:
```powershell
powershell.exe -File scripts/start-backend.ps1 -Dev -Migrate
```

### Q: 如何跳过迁移检查直接启动?

A: 在交互提示中选择 `[N]` 或 `[S]`。

### Q: 数据库已是最新版本,还能手动触发迁移吗?

A: 可以,即使数据库已是最新,交互提示仍允许选择 `[Y]` 执行迁移。

### Q: CI/CD 环境如何配置?

A: 使用 `-Migrate` 参数自动执行迁移:
```yaml
# GitHub Actions 示例
- name: Start Backend
  run: powershell.exe -File scripts/start-backend.ps1 -Prod -Migrate
```

### Q: 如何查看迁移历史?

A: 在交互提示中选择 `[V]`,会显示详细的迁移历史记录。

## 注意事项

1. **交互模式**: 默认情况下,脚本会在交互式终端中显示提示
2. **自动化部署**: 使用 `-Migrate` 参数确保自动化流程顺利进行
3. **错误处理**: 即使迁移失败,服务仍会继续启动(会显示警告)
4. **版本匹配**: 脚本会逐行解析 Alembic 输出,提取版本号
5. **日志记录**: 所有操作都会记录详细日志,便于问题排查
